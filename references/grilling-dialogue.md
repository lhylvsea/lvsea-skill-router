# Grilling 式有限提问

本路由器吸收 `grilling` 的“设计树 / 当前决策前沿 / 推荐答案”机制，但默认采用有边界的版本，避免简单任务被无限追问。

## 先查事实，再问决策

文件、网页可访问性、项目结构、可用 Skill、依赖和已有输出是代理的事实工作。先自行读取和检查，不把这些问题抛给用户。

用户只需要决定会改变目标或路线的事项，例如：

- 最终要 `.pptx` 还是 HTML；
- 要横屏无旁白，还是竖屏配音；
- 要静态可读的实况卡，还是可交互网页；
- 要公开发布还是只保存在本机；
- 要忠实还原参考，还是允许重新设计。

## 轮次规则

1. 根据已经确定的前置条件建立当前 frontier；
2. 同一轮可以问互不依赖的多个决策，最多 3 个；
3. 每个问题编号、给出 2–3 个选项、标注推荐答案和理由；
4. 发出本轮问题后等待用户回答，再重新计算 frontier；
5. 默认最多 2 轮；完成路线选择后停止提问并执行；
6. 用户说“拷问我”“压力测试方案”时，允许进入完整 Grilling 模式，但仍不能把事实查找伪装成用户决策。

## 默认提问格式

```text
❓ Q1｜交付形态：你最终要哪一种？

A. 可编辑 PPTX
B. 可直接打开的 HTML 页面
C. 先做两种关键帧让我比较

➡️ 推荐：C，因为当前材料可以合理落入两种不同交付路线，先看视觉方向能减少返工。
```

直接执行时使用：

```text
我会按推荐路线执行：<route>。
当前假设：<低风险假设>。
如果你没有异议，我继续生成预览/成品并做验收。
```

## 停止条件

- 交付物、主要视觉/工程方向、权限边界和验收标准已确定；
- 用户选择了方案或明确授权按推荐方案执行；
- 剩余事项只是可以记录的低风险细节。

不要为了“把所有分支都问完”而延迟已授权的工作。
